# DOMOTIQ — Smart Home Automation System

A Java Swing desktop application for registering, organising, monitoring and
controlling simulated smart home devices, backed by MySQL through plain JDBC.

> **Simulated devices only.** DOMOTIQ v1 models IoT hardware realistically in
> software — power state, settings, connectivity and sensor telemetry are
> generated by an in-app simulator. No physical devices are controlled.

## Tech stack

| Layer        | Technology                                    |
|--------------|-----------------------------------------------|
| Language     | Java 21+ (built and tested on JDK 26)         |
| GUI          | Java Swing (no HTML/CSS/JS)                   |
| Backend      | Core Java, MVC-style layering                 |
| Database     | MySQL 8.x                                     |
| Connectivity | JDBC (`mysql-connector-j`), PreparedStatements |
| Build        | Maven                                         |

No Hibernate, no Spring Boot.

## Architecture

```
com.domotiq
├── Main                     entry point (DB check -> login window)
├── config    DatabaseConfig env vars > config/domotiq.properties; no hardcoded creds
├── db        DatabaseConnection
├── util      PasswordHasher  PBKDF2-HMAC-SHA256 + per-user salt
├── model     User, Room, ActivityLog, Device (abstract), DeviceType
│   └── devices  SmartLight, SmartFan, SmartAirConditioner,
│                SmartDoorLock, SmartCamera, SmartSensor
├── factory   DeviceFactory   DeviceType -> concrete class
├── repository UserRepository, RoomRepository, DeviceRepository,
│              ActivityLogRepository  (SQL only; device_settings key/value)
├── controller AuthController, DeviceController, RoomController,
│              ActivityController  (validation + persistence + activity log)
├── simulation DeviceSimulator  javax.swing.Timer, live sensor telemetry
└── gui       LoginFrame, RegistrationDialog, MainFrame, DashboardPanel,
              DevicesPanel, DeviceDialog, DeviceCard, RoomsPanel, RoomDialog,
              HistoryPanel, Theme, UiTables
```

Extensibility: each device category declares its controls via
`Device.SettingDefinition` (slider / combo / toggle). The GUI renders them
dynamically and the DB stores them as key/value rows, so adding a new
category requires only a model class + one `DeviceFactory` case.

## Setup

### 1. Create the database

```bash
mysql -u root -p < database/init.sql
```

Creates schema `domotiq` with tables `users`, `rooms`, `devices`,
`device_settings`, `activity_logs` (PKs, FKs, unique and check constraints).

### 2. Provide credentials (never in source code)

Either environment variables (take priority):

```
DOMOTIQ_DB_URL=jdbc:mysql://localhost:3306/domotiq?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC
DOMOTIQ_DB_USER=<your user>
DOMOTIQ_DB_PASSWORD=<your password>
```

or a local properties file (gitignored):

```bash
cp config/domotiq.properties.example config/domotiq.properties
# then edit db.user / db.password
```

### 3. Run

```bash
mvn package
java -jar target/domotiq-1.0.0.jar
```

or during development: `mvn exec:java`.

## Features

- **Auth** — register/login, PBKDF2 hashed passwords, per-user data isolation.
- **Dashboard** — total/online/offline/active counts, category breakdown,
  quick ON/OFF (Lock/Unlock) controls, recent activity feed.
- **Devices** — add/edit/delete, search, filter by category and room;
  category-specific controls (brightness, fan speed, AC temperature + mode,
  lock state, camera recording/resolution, sensor kind).
- **Rooms** — CRUD; deleting a room unassigns (never deletes) its devices;
  per-room device view.
- **History** — every power, settings, add/delete and connectivity event with
  previous/new status and timestamp.
- **Simulation** — sensors emit drifting temperature/humidity and motion/smoke
  events every 4 s; devices can be manually pushed offline/online; offline
  devices reject commands.
